# Лабораторная работа 8: Аннотации и Stream API

### Задание
Реализовать конвейерную систему динамической обработки текстовых данных (`DataManager`), использующую кастомные аннотации и механизмы рефлексии (Reflection API) для автоматического поиска процессоров, а также многопоточность и Stream API для трансформации коллекций.

### Компоненты приложения
* **@interface DataProcessor** – пользовательская аннотация с runtime-удержанием (`@Retention(RetentionPolicy.RUNTIME)`), маркер для методов, участвующих в конвейере обработки.
* **FilterProcessor** – класс-обработчик, содержащий аннотированный метод для фильтрации строк (отсеивает слова длиной 3 символа и меньше).
* **TransformProcessor** – класс-обработчик, содержащий аннотированный метод для перевода строк в верхний регистр с логированием имени текущего потока.
* **DataManager** – управляющий класс. Загружает текстовые данные из файла, регистрирует модули процессоров, сканирует их методы через Reflection API, динамически формирует и запускает цепочку стримов, после чего сохраняет результат.
* **Main** – главный класс, демонстрирующий сквозной сценарий работы: создание демонстрационного файла `input.txt`, инициализацию менеджера, параллельную обработку и вывод итогового файла `output.txt`.

### Ключевые технологии и особенности
* **Метапрограммирование (Reflection API):** Динамический поиск методов, помеченных аннотацией `@DataProcessor`, и их вызов на зарегистрированных объектах через `method.invoke()`. Это позволяет гибко масштабировать систему и добавлять новые шаги обработки без изменения ядра `DataManager`.
* **Асинхронное выполнение (Concurrency):** Вынос вычислений в отдельный рабочий поток пула с помощью `ExecutorService` и получение отложенного результата через объект `Future`.
* **Потоки данных (Stream API):** Последовательное применение промежуточных операций (`filter`, `map`) к потоку строк и последующая терминальная сборка (`Collectors.toList()`) в единую коллекцию.
